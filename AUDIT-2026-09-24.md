## 2. Logic

### Still in good shape

- **IEP** (`src/lib/medicare/iep.ts`). The window ends at 23:59:59.999 on the last day. A birthday on the 1st is centered on the prior month. The Part B tip uses the post-2023 rule (eligibility month or the last three months → the 1st of the next month). Covered by `src/lib/medicare/iep.test.ts`.
- **AEP checklist** points at this fall’s notice for **2027** plan changes (`src/components/tools/aep-checklist-tool.tsx`). Checks persist in `localStorage` key `fmt-aep-checklist-v1`.
- **Working past 65** starts with every box unchecked (`src/components/tools/working-past-65-tool.tsx`), so the first result is the cautious one.
- **Penalty math** is still a one-year extra at 2026 rates, and the on-page notes say both penalties are typically lifelong (`src/lib/medicare/penalties.ts`). Calculated `$0.00` / “$0 Part B late penalty” appears only when the math is zero or the rounding unit is $0.10. That is not a premium advertisement.
- **2026 premiums and the IRMAA dollar amounts** in `src/lib/medicare/constants.ts` still match the CMS table ($202.90 through $689.90 Part B; Part D IRMAA $0 through $91.00).

### Should-fix logic (unchanged, still real)

**1. IRMAA treats $500,000 and $750,000 as the lower tier.**
CMS and the Federal Register: individual MAGI **greater than or equal to $500,000** (joint **$750,000**) is the top tier, Part B **$689.90** and Part D IRMAA **$91.00**. The band under that is **less than** $500,000 / $750,000, at $649.20 / $83.30.

`lookupIrmaa` (`src/lib/medicare/decisions.ts`) returns a bracket when `income > min && income <= max`. Tier 4’s `singleMax` is `500000` and `jointMax` is `750000` (`src/lib/medicare/constants.ts`). So:

- $499,999 single → $649.20 (correct)
- **$500,000 single → $649.20 (one tier low; CMS is $689.90)**
- $500,001 single → $689.90 (correct)
- The same split at **$750,000** joint

The on-screen top row already says “$500,000 and above” (`rangeLabel` in `src/components/tools/irmaa-checker-tool.tsx`). At exactly $500,000 the highlight stays on “Above $205,000 through $500,000.” The label and the lookup disagree at that one dollar. Married filing separately at $391,000 already uses `>=` for the top tier. The individual and joint cliffs should use the same idea: `$500,000` and `$750,000` belong in the top tier.

**2. Married filing separately, lived apart all year.**
The checker always uses the compressed three-tier table. CMS uses the individual table when the person lived apart from their spouse for the entire tax year. The control does not say “lived with your spouse at any time during the year.”

**3. “Single” leaves out other individual filers.**
Head of household and qualifying surviving spouse use the individual column (SSA IRMAA tables). The button only says “Single.”

**4. Part A late penalty is not mentioned.**
The estimator is Part B and Part D only (`src/lib/medicare/penalties.ts` has no Part A note). Someone who pays a Part A premium can owe a Part A penalty. One sentence on the tool is enough so a $0 Part B/D result is not read as “no late penalty of any kind.”

**5. Medigap chart gaps.**
`src/lib/medicare/medigap.ts` and the compare tool still have no Massachusetts, Minnesota, or Wisconsin caveat, no high-deductible F or G, and no note that the Plan N emergency-room copay is waived if the person is admitted. The letters that are on the chart were checked on 23 September and the file has not been reworked since.

**6. Working-past-65 caveats still missing.**
The age-65, 20-employee rule is what the tool implements. It still does not say that disability uses the 100-employee threshold, whose employer the “20 or more” box refers to when a spouse’s plan is checked, or that premium-free Part A can be retroactive up to six months and disturb earlier HSA contributions. The first checkbox still reads “or I am actively employed,” which can be checked without coverage based on current employment.

**7. Penalty promise on the hub does not match the result.**
The calculator heading and notes say the big number is **one year**. The tool blurb, which is also the live meta description on https://freemedicaretools.com/tools/penalty-estimator, says the penalties “could cost **for life**” (`src/lib/medicare/tools.ts`). Both facts are true in different sentences. Side by side they read as if the dollar figure is a lifetime total. The home “You get” line already says “for one year” (`src/app/page.tsx`). Make the blurb match that, and keep the lifelong note where it already sits, under the result.

## 3. PHI and the new privacy page

The privacy page matches the code on the points that matter.

| Claim on `/privacy` | Code |
| --- | --- |
| Tools are not posted to a server | No `app/api` route. Worksheet uses `sessionStorage` only (`saveWorksheet` / `loadWorksheet`). |
| Worksheet stays in this tab and clears when the tab closes, or on “Clear worksheet” | `fmt-client-worksheet-v1`. `clearEverything` removes the key and resets the form. A blank form also calls `clearWorksheet`. |
| Email to agent does not include the worksheet | `src/components/tools/client-worksheet-print.tsx` builds a fixed body: “This message does not include my worksheet.” |
| MBI and SSN are not requested | Still true. Free-text notes can still hold them. The form tells the person not to type them. |
| AEP checks stay in `localStorage` on the device | `fmt-aep-checklist-v1` in `src/components/tools/aep-checklist-tool.tsx`. |

Two gaps on the privacy page, neither of which sends data to the server:

- **“Download CRM JSON”** on the print page writes a local file with the full worksheet (name, date of birth, drugs, Medicaid, VA, notes). The filename includes the person’s name. The button’s note says the file stays on the device. `/privacy` does not mention this download.
- Section 2 says “Through the tools: nothing.” Sections 4 and 5 then explain sessionStorage and localStorage. A person who stops at section 2 can think nothing is stored in the browser at all. The intro line (“nothing you type into them is sent to us”) is the accurate one. Section 2 should use that same meaning.

Print still only requires name and phone (`goToPrint`). The side checklist marks ZIP as its own row, and the ZIP field is not required to continue. That was true on 23 September and is still true.

Other tools (IEP birth date, IRMAA income, penalty months, quiz answers) stay in component state. They are not written to storage.
